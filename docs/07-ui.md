# User Interface: sensor-pages-dashboard

**Last Updated:** 2026-09-23  
**UI Type:** Embedded TFT Display (320×480 pixels)  
**Input Method:** Gamepad buttons (no touchscreen, no settings menu)  
**Navigation:** Circular pagination (10 pages)

---

## Executive Summary

This is a **no-menu, no-hierarchy UI**. The entire application is a series of 10 sensor data pages displayed on a TFT screen. Users navigate between pages sequentially using gamepad buttons (Y = previous, A = next) with automatic wrap-around. Each page displays sensor readings or an error message if the sensor is unavailable.

**No forms, no settings, no configuration UI.** All application behavior is hardcoded at compile-time.

---

## 1. Application Navigation Model

### Navigation Topology: Circular Pagination

The application implements a **circular linked list** of 10 pages. Users navigate sequentially; no skipping or direct access.

```
Page 0 ←→ Page 1 ←→ ... ←→ Page 8 ←→ Page 9 ←→ (wraps to Page 0)
```

**Navigation Rules:**
- **Y Button (Gamepad):** Navigate to previous page (currentPage - 1, mod 10)
- **A Button (Gamepad):** Navigate to next page (currentPage + 1, mod 10)
- **Wrap-around:** From page 0, Y goes to page 9; from page 9, A goes to page 0
- **No history:** No "back stack"; pressing Y repeatedly cycles through all pages in reverse

### Route Model: No Routes

This is not a web application. There are no URL routes, path parameters, or query strings. Navigation is purely sequential page indices (0–8).

| Concept | Implementation |
|---------|---|
| **Current Page** | Global variable `currentPage` (uint8_t, 0–9) |
| **Page Address** | Array index in page renderer switch statement |
| **Navigation** | Direct `currentPage` mutation (no routing library) |
| **Deep Linking** | Not supported; always boots to page 0 (BME280) or page 2 (INA219) |
| **Forward/Back** | Y = back (previous page), A = forward (next page) |

**Display Specs:**

- Orientation: Landscape (rotated 90°)
- Color depth: 16-bit RGB565
- Refresh rate: 20 ms (live pages: Encoder, Gamepad), 500 ms (sensor pages)

**Color Scheme:**

| Color | Usage | Rationale |
|-------|-------|-----------|
| TFT_BLACK (0x0000) | Background | High contrast |
| TFT_CYAN (0x07FF) | Page title header, computed/derived values | Bright, readable in sunlight |

### Page 0: BME280 Climate Sensor

**Route:** Direct (no URL; boot default)  
**Purpose:** Display temperature, humidity, pressure, altitude, dew point from BME280 sensor  
**I2C Address:** 0x77  
**Title Displayed:** "BME280 (0x77)"  

**Layout:**

| Component | Content | Y | Color |
|-----------|---------|---|-------|
| Header | "BME280 (0x77)" | 8 | Cyan |
| Divider | ─────────────── | 38 | Dark Grey |
| Label | "Temperature:" | 56 | White |
| Value | `${temp}°C` (2 decimals) | 56 | Green |
| Label | "Humidity:" | 80 | White |
| Value | `${humidity}%` (2 decimals) | 80 | Green |
| Label | "Pressure:" | 104 | White |
| Value | `${pressure}hPa` (2 decimals) | 104 | Orange |
| Label | "Altitude:" | 128 | White |
| Value | `${altitude}m` (1 decimal) | 128 | Cyan |
| Label | "Dew point:" | 152 | White |
| Value | `${dewPoint}°C` (2 decimals) | 152 | Cyan |
| Footer | "Y/A: Seite wechseln \| BME280" | 294 | Dark Grey |

**Data Retrieval (FEATURE-SPEC-005 Caching Architecture):**
- **Trigger:** I2C reads occur in `readSensors()` every 500 ms via `readBme280()` function
- **Page Function Behavior:** `pageBme280()` reads cached values from global `bme280Values` struct (NO I2C calls during page render)
- **Cached Fields:**
  - `bme280Values.temperature` ← `bme280.readTemperature()` (°C)
  - `bme280Values.humidity` ← `bme280.readHumidity()` (%)
  - `bme280Values.pressure` ← `bme280.readPressure() / 100.0f` (Pa → hPa)
  - `bme280Values.altitude` ← `bme280.readAltitude(1013.25)` (m, 1013.25 hPa reference)
  - `bme280Values.dewPoint` ← computed via Alduchov & Eskridge formula
- **Benefit:** Eliminates I2C latency during page rendering; improves display responsiveness

**Computed Values (Alduchov & Eskridge Formula, ±0.35°C accuracy, valid 0-50°C / 1-100% RH):**
```cpp
// Computed in readBme280() every 500ms, cached for display
const float a = 17.62;
const float b = 243.12;
float alpha = ((a * temperature) / (b + temperature)) + log(humidity / 100.0f);
dewPoint = (b * alpha) / (a - alpha);  // Result in °C
```
**Note:** Requires `#include <math.h>` for `log()` function. More accurate than simplified formula (±3°C).

**Sensor Missing Behavior:**
If BME280 not detected at boot (`available.bme280 = false`):
- Header displays normally ("BME280 (0x77)")
- Error screen shows "Sensor nicht vorhanden" (red, font 2)
- I2C address displayed in yellow (0x77)
- Footer shows "Keine Daten verfuegbar"
- Navigation still works (Y/A buttons)

**User Actions:**
- **Y Button:** Navigate to page 8 (VEML6075)
- **A Button:** Navigate to page 1 (Gamepad QT)
- **No other interactions**

**Permissions:** None (embedded firmware; no auth model)

| Footer | "Y/A: Seite wechseln \| INA219" | 294 | Dark Grey |

**Data Display:**
- Bus voltage: 0–26V (3 decimals)
- Shunt voltage: usually ±0.08V (3 decimals, negated from sensor)
- Load voltage: Bus - Shunt/1000 (3 decimals)
- Current: Negated from sensor (inverted sign; 3 decimals)
- Power: Product of voltage × current (3 decimals)
- Charge (Coulomb counter): Accumulated mAh, never reset (3 decimals, unbounded, resets on reboot)

**Data Retrieval:**
- **Trigger:** Every 20 µs (50 Hz via `micros()`)
- **I2C Calls:**
  - `getShuntVoltage_mV()` → shunt (negated)
  - `getBusVoltage_V()` → bus
  - `getCurrent_mA()` → current (negated)
  - `getPower_mW()` → power

**Coulomb Accumulation:**
```
chargeMah += current_mA * elapsed_µs / 3.6e9  (every 20 µs, if elapsed < 200ms)
```

#### Page 2 Alternate View: Large Value Display Mode — **NEW**

**Route:** Direct (Page 2 with mode flag)  
**Purpose:** Alternate display mode for INA219 showing individual sensor values in large, centered format  
**Entry:** Press Gamepad Button B while viewing Page 2 (standard layout)  
**Exit:** Press Gamepad Button Y while in large display mode  

**Layout (Large Display Mode):**

```
┌─────────────────────────────────────────┐
│                                         │
│ [LABEL - centered, Font 4]              │  e.g., "Laufzeit"
│                                         │
│ [VALUE - centered, Font 8 (VERY LARGE)] │  e.g., "123456"
│                                         │
│ [UNIT - centered, Font 2]               │  e.g., "s"
│                                         │
│ [FOOTER - centered, Font 1]             │  "B:next X:prev Y:exit"
│                                         │
└─────────────────────────────────────────┘
```

**Key Differences from Standard Page 2:**
- No page header/title (alternate layout maximizes space for value)
- No data rows (standard multi-row layout replaced)
- Single value displayed at a time (vs. 7 rows in standard view)
- Very large Font 8 for value (vs. Font 2 in standard view)
- Colored value (Font 8) matching standard page color scheme
- Centered alignment (vs. left-aligned in standard view)
- Footer shows mode-specific instructions (B:next, X:prev, Y:exit)

**Navigation Within Large Display Mode:**
- **Button B (Forward Cycle):** Advance to next value in list (wraps from index 6 → 0)
- **Button X (Reverse Cycle):** Go to previous value in list (wraps from index 0 → 6)
- **Button Y (Exit):** Return to standard Page 2 layout
- **Button A (Inactive):** No effect (page navigation disabled during mode)

**7-Value Display Cycle (Index 0–6):**

| Index | Label | Value | Unit | Color |
|-------|-------|-------|------|-------|
| 0 | Laufzeit | Runtime (seconds) | s | Cyan |
| 1 | Batterie | Bus voltage | V | Green |
| 2 | Versorgung | Shunt voltage | mV | Green |
| 3 | Strom | Current | mA | Orange |
| 4 | Ladung | Accumulated charge | mAh | Cyan |
| 5 | Shunt-Spannung | Load voltage | V | Green |
| 6 | Power | Power | mW | Orange |

**Value Formatting (Identical to Standard Page):**
- Laufzeit: Integer (no decimals)
- All other values: 3 decimal places
- Formatting functions: `getLargeDisplayValue(index)` returns formatted String
- Color applied via `getLargeDisplayColor(index)`
- Unit label via `getLargeDisplayUnit(index)`

**Real-Time Updates:**
- Values refreshed every 500 ms (inherited from Page 2 native rate)
- No forced higher refresh rate
- Direct read from global `ina219Values` struct (no caching)
- Reflects latest sensor measurement within standard 500 ms poll cycle

**Critical Constraints:**
- **Page Navigation Disabled:** While in large display mode, Y/A buttons are NOT available for page navigation (Y = exit mode, A = inactive)
- **Button Behavior Context-Sensitive:** Same buttons have different meanings in each mode:
  - Standard Page 2: Y = previous page, A = next page
  - Large Display Mode: Y = exit, A = inactive
  - Navigation re-enabled immediately after exit via Y
- **Mode Exit Behavior:** Pressing Y clears `largeDisplayMode` flag and returns to standard Page 2 view with `largeDisplayIndex` reset to 0

**User Experience:**
1. User on Page 2 presses Button B → Enters large display mode at index 0 (Laufzeit/Runtime)
2. User presses Button B repeatedly → Cycles forward through indices 1→2→3→4→5→6→(wrap to 0)
3. User presses Button X repeatedly → Cycles backward through indices 6→5→4→3→2→1→(wrap to 0)
4. User presses Button Y → Exits large display mode, returns to standard Page 2 view
5. User presses Button A at any point in large display → No effect (button inactive)

**Data Retrieval:**
- **Trigger:** Every 500 ms (standard page refresh cycle)
- **Functions Called:**
  - `pageLargeDisplayIna219(largeDisplayIndex)` — Main renderer (conditional in `pageIna219()`)
  - `getLargeDisplayLabel(index)` — Returns German label
  - `getLargeDisplayValue(index)` — Reads and formats value from struct
  - `getLargeDisplayUnit(index)` — Returns unit string
  - `getLargeDisplayColor(index)` — Returns color constant

**Sensor Missing Behavior:**
If INA219 not detected at boot (`available.ina219 = false`):
- User cannot enter large display mode (no Page 2 content to interact with)
- Standard page shows error screen ("Sensor nicht vorhanden")
- Button B press ignored (page locked to error view)

**Button Behavior in Large Display Mode (Detailed):**
```
User presses Button B (on Page 2, largeDisplayMode = false):
  → largeDisplayMode = true
  → largeDisplayIndex = 0
  → Next cycle: pageLargeDisplayIna219(0) renders

User presses Button B (on Page 2, largeDisplayMode = true):
  → largeDisplayIndex = (0 + 1) % 7 = 1
  → Next cycle: pageLargeDisplayIna219(1) renders

User presses Button X (on Page 2, largeDisplayMode = true):
  → largeDisplayIndex = (1 - 1 + 7) % 7 = 0
  → Next cycle: pageLargeDisplayIna219(0) renders

User presses Button Y (on Page 2, largeDisplayMode = true):
  → largeDisplayMode = false
  → largeDisplayIndex = 0 (reset)
  → Next cycle: pageIna219() renders standard layout

User presses Button A (on Page 2, largeDisplayMode = true):
  → No action (button inactive during mode)
  → Display unchanged
```

**Permissions:** None

**Data Display:**

**Data Retrieval (FEATURE-SPEC-005 Caching Architecture):**
- **Trigger:** I2C reads occur in `readSensors()` every 500 ms via `readTsl2591()` function
- **Page Function Behavior:** `pageTsl2591()` reads cached values from global `tsl2591Values` struct (NO I2C calls during page render)
- **Cached Fields:**
  - `tsl2591Values.fullSpectrum` ← Lower 16 bits of `getFullLuminosity()` (CHAN0: visible + infrared)
  - `tsl2591Values.infrared` ← Upper 16 bits of `getFullLuminosity()` (CHAN1: infrared only)
  - `tsl2591Values.visible` ← Computed: `fullSpectrum - infrared` (or 0 if negative)
  - `tsl2591Values.lux` ← `calculateLux(fullSpectrum, infrared)` (Adafruit algorithm)
  - `tsl2591Values.gain` ← `getGain()` (for reference; typically 1x/25x/428x/9876x)
  - `tsl2591Values.integrationTime` ← `getTiming()` (for reference; typically 100–600 ms)
- **Bitwise Extraction:** `getFullLuminosity()` returns uint32_t encoded as `[CHAN1(16-31) | CHAN0(0-15)]`
- **Benefit:** Eliminates I2C latency during page rendering; improves display responsiveness
- **Error Detection:** Zero-value check prevents stale data from corrupted I2C reads

## 5. Navigation Behavior

### Page Transition

**Trigger:** Y or A button falling edge detected (transition from released to pressed).

**Behavior:**

1. **Gamepad read completes** (25 ms cycle)
2. **Button state compared** to previous state (edge detection)
3. **If Y pressed (falling edge):** `currentPage = (currentPage + 10 - 1) % 10` (previous)
4. **If A pressed (falling edge):** `currentPage = (currentPage + 1) % 10` (next)
5. **Page index updated**
6. **Next loop cycle:** `if (currentPage != lastPage) drawCurrentPage(true)` (full redraw with header)
7. **lastPage updated** to match currentPage

**Wrap-Around:**
- Page 0 Y button → Page 9
- Page 9 A button → Page 0

**Transition Speed:** Up to 25 ms (gamepad read frequency).

**No Animation:** Immediate switch; no slide/fade effect.

---

### Page Rendering Decision

**On Each Loop Cycle:**

```cpp
if (currentPage != lastPage) {
  drawCurrentPage(true);      // Full redraw (header + data)
  lastPage = currentPage;
} else if (IS_LIVE_PAGE && time_gate_fires) {
  drawCurrentPage(false);     // Data-only refresh (no header)
} else if (time_gate_fires) {
  drawCurrentPage(false);     // Data-only refresh
}
```

**Live Pages:** Gamepad (page 2), Encoder (page 4) → 20 ms refresh
**Slow Pages:** All others → 500 ms refresh

## 6. Interaction Patterns

### Button Press Edge Detection

**Pattern:** Debounce via state tracking

```
Previous cycle: button_state = 1 (released)
Current cycle:  button_state = 0 (pressed)
Edge detected?  Yes (1→0 transition)
Action:         Execute navigation / LED change
Save state:     For next cycle comparison
```

**Debounce:** Hardware debounce on gamepad seesaw; no software debounce.

**Double-Press:** Each press counted independently; no multi-tap logic.

---

### Encoder Interaction

**Dial Rotation:**
1. Dial rotated
2. `readEncoderAt50Hz()` called (page 4 active or page changing)
3. Position delta calculated
4. LED brightness adjusted (delta × 8)
5. `updateEncoderLed()` called (immediate NeoPixel update)
6. Next page refresh: new brightness displayed

**Button Press:**
1. Button pressed (falling edge)
2. Press count incremented
3. Color index cycled (0→1→2→3→0)
4. `updateEncoderLed()` called (immediate)
5. Next page refresh: new color name displayed

**Latency:** 20 ms (read cycle), + SPI time for LED update.

**Constraint:** `0 <= currentPage < 10`

**Enforcement:** Modulo arithmetic on all navigation operations.

**Example:**
```cpp
currentPage = (currentPage + 1) % 10;  // Always results in 0–9
currentPage = (currentPage + 10 - 1) % 10;  // Always results in 0–9
```

**Display Precision:**
- Temperatures: 2 decimals (float format "%.2f")
- Voltages: 3 decimals
- Pressures: 2 decimals

- Altitude: 1 decimal
- Other ADC values: No decimals (integer display)

**No Validation:** Values displayed as-is; no range checks (except LED brightness clamping).

**Trigger:** Button Y pressed while in large display mode

1. Set `largeDisplayMode = false`, `largeDisplayIndex = 0` (reset state)

3. No visual artifacts; clean transition

- **Refresh Rate:** Inherited from page 2 standard refresh (500 ms)
- **Data Source:** Live `ina219Values` struct (no caching)
- **Display Latency:** Up to 500 ms between value changes and display update
- **Consistency:** Value formatting (decimal places) matches standard page exactly

### 7.6 Performance & Constraints

- **Render Time:** ~450 ms (must complete within 500 ms refresh cycle)
- **Memory:** Direct rendering (no buffering; no Sprite allocation)
- **Flash Impact:** +~500 bytes for helper functions and layout code
- **Dependencies:** Requires `available.ina219 == true`
