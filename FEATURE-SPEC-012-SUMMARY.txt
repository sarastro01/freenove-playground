2. ENHANCED LOGGING: Timestamps [HH:MM:SS.sss]
   ──────────────────────────────────────────
   Status: READY FOR IMPLEMENTATION
   
   Implementation: Create logPrintf() wrapper function
   - Prepends timestamp to every Serial.printf() call
   - Format: [HH:MM:SS.sss] (13 chars)
   - Uses integer-only arithmetic (no floating point)
   
   Performance Impact:
   - Per-message overhead: ~50-100 μs (negligible)
   - Code size: +500 bytes
   - Memory stack: +50 bytes
   - Loop impact: NONE (not on critical path)
   - Serial throughput: OK at 115200 baud
   
   Files to Update:
   - src/main.cpp: Add logPrintf() wrapper, replace all Serial.printf()
   - src/diagnostics.h: Add version/date constants
   - src/sensors/EncoderSensor.cpp: Add input logging
   - src/sensors/GamepadSensor.cpp: Add input logging

3. DISPLAY DIAGNOSTICS: Log Spontaneous Switches & Input Activity
   ──────────────────────────────────────────────────────────────
   Status: READY FOR IMPLEMENTATION
   
   Problem: Display switches pages without user interaction
   
   Solution: Comprehensive logging of:
   - Every page change with reason (GAMEPAD/ENCODER/AUTO)
   - Encoder rotations (position, delta, direction)
   - Encoder button press/release
   - Gamepad button state changes
   - Large Display Mode entry/exit
   
   Analysis Strategy:
   - Capture 24-hour log
   - Identify page switches NOT preceded by input logs
   - Correlate with encoder/gamepad events
   - Investigate root causes:
     a) Electrical noise (encoder capacitive coupling)
     b) I2C read errors (gamepad phantom events)
     c) Timer overflow (signed comparison bugs)
     d) Interrupt handlers (seesaw library)
   
   Log Categories:
   [BOOT], [DIAG], [SENSOR], [INPUT], [MODE], [I2C], [ERROR], [VERSION]
