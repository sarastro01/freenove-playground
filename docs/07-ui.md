# User Interface: sensor-pages-dashboard

**Last Updated:** 2026-09-23  
**UI Type:** Embedded TFT Display (320×480 pixels)  
**Input Method:** Gamepad buttons (no touchscreen, no settings menu)  
**Navigation:** Circular pagination (10 pages)

---

## Executive Summary

This is a **no-menu, no-hierarchy UI**. The entire application is a series of 10 sensor data pages displayed on a TFT screen. Users navigate between pages sequentially using gamepad buttons (Y = previous, A = next) with automatic wrap-around. Each page displays sensor readings or an error message if the sensor is unavailable.

**No forms, no settings, no configuration UI.** All application behavior is hardcoded at compile-time.

---

## 1. Application Navigation Model

### Navigation Topology: Circular Pagination

The application implements a **circular linked list** of 10 pages. Users navigate sequentially; no skipping or direct access.

```
Page 0 ←→ Page 1 ←→ ... ←→ Page 8 ←→ Page 9 ←→ (wraps to Page 0)
```

**Navigation Rules:**
- **Y Button (Gamepad):** Navigate to previous page (currentPage - 1, mod 10)
- **A Button (Gamepad):** Navigate to next page (currentPage + 1, mod 10)
- **Wrap-around:** From page 0, Y goes to page 9; from page 9, A goes to page 0
- **No history:** No "back stack"; pressing Y repeatedly cycles through all pages in reverse

### Route Model: No Routes

This is not a web application. There are no URL routes, path parameters, or query strings. Navigation is purely sequential page indices (0–8).

| Concept | Implementation |
|---------|---|
| **Current Page** | Global variable `currentPage` (uint8_t, 0–9) |
| **Page Address** | Array index in page renderer switch statement |
| **Navigation** | Direct `currentPage` mutation (no routing library) |
| **Deep Linking** | Not supported; always boots to page 0 (BME280) or page 2 (INA219) |
| **Forward/Back** | Y = back (previous page), A = forward (next page) |

## 2. Page Specifications

All pages share a common layout and follow the same rendering pattern.

### Common Layout

```
┌─────────────────────────────────────────┐
│ [HEADER - Cyan Title]                   │  y=8, font=4
├─────────────────────────────────────────┤  y=38 (divider line)
│                                         │
│ [DATA ROWS - Label & Value]             │  y=56+ (first row at 56, height 24 per row)
│ [DATA ROWS]                             │
│ [DATA ROWS]                             │
│                                         │
│ [ERROR MESSAGE - If sensor unavailable] │
│                                         │
├─────────────────────────────────────────┤
│ [FOOTER - Footer text]                  │  y=294
└─────────────────────────────────────────┘
```

**Display Specs:**
- Resolution: 320 × 480 pixels
- Orientation: Landscape (rotated 90°)
- Color depth: 16-bit RGB565
- Refresh rate: 20 ms (live pages: Encoder, Gamepad), 500 ms (sensor pages)

**Color Scheme:**

| Color | Usage | Rationale |
|-------|-------|-----------|
| TFT_BLACK (0x0000) | Background | High contrast |
| TFT_CYAN (0x07FF) | Page title header, computed/derived values | Bright, readable in sunlight |
| TFT_WHITE (0xFFFF) | Data labels, default text | Maximum contrast |
| TFT_YELLOW (0xFFE0) | I2C addresses | Bright, readable in daylight |
| TFT_GREEN (0x07E0) | Good readings (raw values, primary sensors) | Indicates healthy values |
| TFT_ORANGE (0xFD20) | Secondary measurements, warnings | Caution indicator |
| TFT_RED (0xF800) | Errors, disconnected sensors | Error indicator |
| TFT_DARKGREY (0x39E7) | Dividers, footers | Subtle separation |

**⚠️ Avoid:** TFT_MAGENTA — Not readable in bright/sunlight environments. Use TFT_CYAN instead for derived values.

**Layout Constants:**
- Title x: 6 px (left margin)
- Title y: 8 px (top margin)
- Divider y: 38 px
- First data row y: 56 px (below divider + margin)
- Row height: 24 px
- Value x: 474 px (right edge = 480 - 6)
- Footer y: 294 px (480 - 186)

| Value | `${altitude}m` (1 decimal) | 128 | Cyan |

| Value | `${dewPoint}°C` (2 decimals) | 152 | Cyan |

**Data Retrieval:**
- **Trigger:** Page rendered; on every 500 ms sensor refresh cycle

**User Actions:**

- **A Button:** Navigate to page 1 (Gamepad QT)
- **No other interactions**

**Permissions:** None (embedded firmware; no auth model)

**Data Display:**
- Bus voltage: 0–26V (3 decimals)
- Shunt voltage: usually ±0.08V (3 decimals, negated from sensor)
- Load voltage: Bus - Shunt/1000 (3 decimals)
- Current: Negated from sensor (inverted sign; 3 decimals)
- Power: Product of voltage × current (3 decimals)
- Charge (Coulomb counter): Accumulated mAh, never reset (3 decimals, unbounded, resets on reboot)

**Data Retrieval:**
- **Trigger:** Every 20 µs (50 Hz via `micros()`)
- **I2C Calls:**
  - `getShuntVoltage_mV()` → shunt (negated)
  - `getBusVoltage_V()` → bus
  - `getCurrent_mA()` → current (negated)
  - `getPower_mW()` → power

**Coulomb Accumulation:**
```
chargeMah += current_mA * elapsed_µs / 3.6e9  (every 20 µs, if elapsed < 200ms)
```

**Data Display:**
- Position: Absolute encoder tick count (int32, can be negative)
- Delta: Difference since last read (int32)
- Button: "PRESSED" or "released"
- Presses: Cumulative count of button presses (never reset except reboot)
- LED color: Current color name (cycles on button press)
- LED brightness: Current brightness 0–255 (adjusted by dial rotation)
- Seesaw temp: Internal seesaw chip temperature (informational)

**Special Behavior:**
- This page is **live** (refreshes every 20 ms)
- **User Interactions:**
  - **Dial rotation:** Brightness changes (delta × 8, clamped 0–255); LED updates immediately (within same cycle)
  - **Button press (falling edge):** Color cycles (blue→green→red→purple→blue); press count increments; LED updates immediately
  - **Y Button:** Navigate to page 2 (INA219)
  - **A Button:** Navigate to page 4 (SCD30)

**LED Control (Immediate):**
- On button press: `updateEncoderLed()` called immediately (NeoPixel I2C command)
- On dial turn: `updateEncoderLed()` called immediately (NeoPixel I2C command)
- LED state synced to display every 20 ms

**Data Retrieval:**
- **Trigger:** Every 20 ms (50 Hz) when page 4 active OR page changing
- **I2C Calls:**
  - `getEncoderPosition()` → position (ticks)
  - `digitalRead(GPIO 24)` → button (active-low)
  - `getTemp()` → seesaw internal temperature

**LED Hardware:**
- Type: WS2812B RGB NeoPixel (1 pixel)
- Color palette: 4 hardcoded RGB values
- Brightness: 0–255 (8-bit PWM)
- Update: SPI via seesaw (immediate, blocking I2C call)

**Sensor Missing Behavior:**
If encoder not detected at boot (`available.encoder = false`):
- Error screen shows "Rotary Encoder" (red)
- I2C address: "0x36" (yellow)
- Footer: "Keine Daten verfuegbar"
- Encoder input disabled entirely (dial/button ignored globally)

**Permissions:** None

**Compensation Formulas:**
```
uvaComp = max(0, uva - 2.22*comp1 - 1.33*comp2)
```

- **I2C Calls:**

  - `readReg16(0x10, 0x09)` → UVB

| Sensor 1 ID | "Sensor 1 ID: 28:AB:CD:EF:01:02:03:04" | 90 | 2 | White/Yellow |
| Sensor 1 Temp | Temperature (e.g., "20.50 °C") or "Disconnected" | 116 | 2 | Cyan/Red |
| **Sensor 2** | | | | |
| Sensor 2 ID | "Sensor 2 ID: 28:AB:CD:EF:01:02:03:05" | 158 | 2 | White/Yellow |
| Sensor 2 Temp | Temperature (e.g., "24.12 °C") or "Disconnected" | 184 | 2 | Cyan/Red |
| **Sensor 3** | | | | |
| Sensor 3 ID | "Sensor 3 ID: 28:AB:CD:EF:01:02:03:06" | 226 | 2 | White/Yellow |

| Footer | "Y/A: Seite wechseln \| DS2484" | 294 | 1 | Dark Grey |

**Spacing Calculation:**
- Starting Y: 90 (first sensor ID position)
- Label-to-Value offset: +26 pixels
- Value-to-Next-Label offset: +42 pixels (26 + 16 gap)
- Effective spacing per sensor: 68 pixels (26 + 42)
- Maximum display capacity: 3 sensors (positions 90, 158, 226)

**ROM-ID Format:**
- Full 8-byte hexadecimal: "28:AB:CD:EF:01:02:03:04"
- First byte: Family Code (0x28=DS18B20, 0x22=DS1822, 0x10=DS1820)
- Bytes 1–6: Serial number (unique per device)
- Byte 7: CRC checksum

**Status Display Rules:**
- If `ds2484Values.sensorCount == 0`: Display "OK - No Sensors Found"
- If `ds2484Values.sensorCount > 0`: Display "OK - X Sensors" (e.g., "OK - 3 Sensors")
- For each detected sensor:
  - If `sensor.available == true`: Display temperature (2 decimals, e.g., "23.45 °C") in Cyan
  - If `sensor.available == false`: Display "Disconnected" in Red

**Sensor Discover & Update Timing:**
- **Bus Scan:** Every 60 seconds (detect new/missing sensors)
- **Temperature Update:** Every 3 seconds (read current values)
- Display shows most recent values after each successful read

**Refresh Behavior:**
- Header and footer fixed (no refresh)
- Sensor IDs update only after 60-second bus scan (static during 3-second polling)
- Temperatures update every 3 seconds (dynamic)
- Status line updates after each operation

**User Actions:**
- **Y Button:** Navigate to page 8 (VEML6075)
- **A Button:** Navigate to page 0 (BME280) [wraps around]
- **No other interactions**

**Sensor Missing Behavior:**
If DS2484 not detected at boot (`available.ds2484 = false`):
- Error screen shows "DS2484 1-Wire" (red)
- I2C address: "0x18" (yellow)
- Footer: "Keine Daten verfuegbar"

**Permissions:** None

### I2C Read Failure (Silent)

**Trigger:** Sensor read fails mid-session (I2C error, timeout, CRC fail).

**Display:**  
Page continues to show last-known values (stale data).

**Behavior:**
- No error message displayed
- Data appears "live" but is frozen
- No indication of staleness
- Gamepad button page navigation still works

**Causes:**
- I2C bus busy / conflict
- Device not responding
- CRC validation failure (SCD30)
- Connection loose

## 4. Components & Patterns

### Header Component

**Used On:** Every page (conditionally redrawn)

**Rendering:**

```cpp
void drawHeader(const char *title) {
```

**When Redrawn:**
- Page changes (currentPage != lastPage)

**Reuse:** Conditional; skipped for data-only refreshes (performance).

### Data Row Component

**Used On:** All pages (sensor data display)

**Rendering:**

```cpp
void row(int y, const char *label, const String &value, uint16_t color = TFT_WHITE) {
  writeText(6, y, label, TFT_WHITE);                  // Left-aligned label
  tft.setTextColor(color, TFT_BLACK);

```

**Parameters:**

- value: Right text (colored, font 2, right-aligned to x=474)
- color: Value text color (default white, can be green/orange/cyan/red; never magenta — not readable in sunlight)

**Reuse:** Every sensor page (10+ rows per page).

## 5. Navigation Behavior

### Page Transition

**Trigger:** Y or A button falling edge detected (transition from released to pressed).

**Behavior:**

1. **Gamepad read completes** (25 ms cycle)
2. **Button state compared** to previous state (edge detection)
3. **If Y pressed (falling edge):** `currentPage = (currentPage + 10 - 1) % 10` (previous)
4. **If A pressed (falling edge):** `currentPage = (currentPage + 1) % 10` (next)
5. **Page index updated**
6. **Next loop cycle:** `if (currentPage != lastPage) drawCurrentPage(true)` (full redraw with header)
7. **lastPage updated** to match currentPage

**Wrap-Around:**
- Page 0 Y button → Page 9
- Page 9 A button → Page 0

**Transition Speed:** Up to 25 ms (gamepad read frequency).

**No Animation:** Immediate switch; no slide/fade effect.

---

### Page Rendering Decision

**On Each Loop Cycle:**

```cpp
if (currentPage != lastPage) {
  drawCurrentPage(true);      // Full redraw (header + data)
  lastPage = currentPage;
} else if (IS_LIVE_PAGE && time_gate_fires) {
  drawCurrentPage(false);     // Data-only refresh (no header)
} else if (time_gate_fires) {
  drawCurrentPage(false);     // Data-only refresh
}
```

**Live Pages:** Gamepad (page 2), Encoder (page 4) → 20 ms refresh
**Slow Pages:** All others → 500 ms refresh

## 6. Interaction Patterns

### Button Press Edge Detection

**Pattern:** Debounce via state tracking

```
Previous cycle: button_state = 1 (released)
Current cycle:  button_state = 0 (pressed)
Edge detected?  Yes (1→0 transition)
Action:         Execute navigation / LED change
Save state:     For next cycle comparison
```

**Debounce:** Hardware debounce on gamepad seesaw; no software debounce.

**Double-Press:** Each press counted independently; no multi-tap logic.

---

### Encoder Interaction

**Dial Rotation:**
1. Dial rotated
2. `readEncoderAt50Hz()` called (page 4 active or page changing)
3. Position delta calculated
4. LED brightness adjusted (delta × 8)
5. `updateEncoderLed()` called (immediate NeoPixel update)
6. Next page refresh: new brightness displayed

**Button Press:**
1. Button pressed (falling edge)
2. Press count incremented
3. Color index cycled (0→1→2→3→0)
4. `updateEncoderLed()` called (immediate)
5. Next page refresh: new color name displayed

**Latency:** 20 ms (read cycle), + SPI time for LED update.

---

## 7. Validation Rules

### Page Index Validation

**Constraint:** `0 <= currentPage < 10`

**Enforcement:** Modulo arithmetic on all navigation operations.

**Example:**
```cpp
currentPage = (currentPage + 1) % 10;  // Always results in 0–9
currentPage = (currentPage + 10 - 1) % 10;  // Always results in 0–9
```

### Data Formatting

**Display Precision:**
- Temperatures: 2 decimals (float format "%.2f")
- Voltages: 3 decimals
- Pressures: 2 decimals
- UV Index: 2 decimals
- Altitude: 1 decimal
- Other ADC values: No decimals (integer display)

**No Validation:** Values displayed as-is; no range checks (except LED brightness clamping).
